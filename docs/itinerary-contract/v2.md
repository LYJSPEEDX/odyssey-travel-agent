# Odyssey itinerary v2 — shared Android/backend contract

The canonical contract is [frontend-itinerary-v2.schema.json](frontend-itinerary-v2.schema.json):
`contractId: "odyssey.frontend.itinerary"`, `schemaVersion: "2.0"`.
`POST /trips` and `POST /trips/preview` return this document directly, without a response envelope.
Android accepts it through `SavedTrip.fromContract` and continues to read frontend v1.
The planning-session API exports a `TripRequest`, not an itinerary. Generation-job/SSE APIs remain unimplemented.

## Assembly and unknown facts

Research and scheduling retain their internal models. The backend assembler maps them into
`requestSnapshot`, `summary`, `places`, `transportGroups`, `stayGroups`, `days`, `money`,
`budget`, and `quality`. Global IDs are namespaced independently of provider IDs.
`planningOptionId` identifies the candidate actually used by the schedule and budget.

Generated documents have `dataMode: LIVE`, `status: PARTIAL`, and a partial budget.
LIVE means provider-backed research, not verified booking availability or completeness.
Traveler ages/passports, room types/capacity, location country/timezone metadata not supplied
by providers, baggage weight, and self-transfer status stay null. Constraints preserve their
original descriptions with UNSPECIFIED strength and UNVERIFIED checks. The original free-text
budget and companion description remain in request notes; no numeric budget is inferred.
Meal type may be UNKNOWN. Unknown values are valid v2 states, not fictional placeholders.

No cover image, entry rule, exchange rate, hotel check-in time, or local transfer is invented.
Hotel photos are omitted until their provider/attribution can be represented correctly.
Actual booking URLs are retained as quote source URLs when supplied. Missing sources remain
UNVERIFIED. Source timestamps record assembly time, not an upstream availability guarantee.

## Dates and return fares

`requestSnapshot.requestedEndDate` retains the requested destination-departure date and
`returnDateMeaning` is LEAVE_DESTINATION. Summary/days cover actual outbound departure
through arrival home, including empty travel days and cross-day transport continuations.
The full journey must fit 60 calendar days; assembly rejects longer journeys without truncating (409 UNSUPPORTED_JOURNEY_TIMELINE).
Journeys with reversed local calendar dates across the date line also return this explicit error;
the current day-by-day UI cannot represent them safely.
Flight moments preserve airport offsets and IANA time zones. Invalid/overlapping timelines fail validation.

Outbound and inbound groups share the same return-fare cost ID. Option index N in each
direction belongs to the same return offer; they cannot be independently mixed or priced.
Android currently compares options without switching. Supporting independent selection will
require explicit return-offer pairing and rescheduling. Comparison candidates with different
endpoint airports are omitted with a visible notice; connecting airports are preserved as legs.

## Money

Quotes cover the entire party: a return fare once and all rooms for the entire hotel stay.
They are represented as PARTY × 1 to avoid per-night/per-person rounding or double counting.
Only costs from the selected plan enter activeCostItemIds; alternative quotes do not.
Foreign currency quotes keep originalTotal but have null displayTotal without a verified FX rate.
Subtotal sums known display amounts only. Contingency is zero with a notice that no allowance
was applied. Unknown fees/meals/activities/transfers are excluded, not advertised as free.
Currency metadata uses the existing provider money helper, including JPY zero decimal digits.

## Validation, deployment and legacy data

The canonical schema is copied into `backend/app/contracts/` for backend-only deployments.
After schema edits run `python -m scripts.sync_itinerary_schema` from backend; a test rejects drift.
Deploy the whole app directory, including contracts/*.json. Runtime validation has no dependency on docs/.
Schema validation is followed by global-ID/reference, selection, timestamp, chronology, day,
quantity, currency-conversion, active-cost and subtotal checks.

Run backend unit tests and `python docs/itinerary-contract/validate_examples.py` from the repository root.
[backend-generated-frontend-v2.json](examples/backend-generated-frontend-v2.json) is exact output
from deterministic research/schedule fixtures. Python tests detect output drift, and Android
instrumentation tests parse, save and render the same artifact alongside existing v1/v2 fixtures.
Regenerate it with `python -m scripts.export_itinerary_fixture` from backend.

[Legacy backend v2](legacy-backend-v2.md) also used schemaVersion 2.0 but lacked contractId
and had different fields. It is no longer generated. Stored data is not migrated or deleted;
GET /trips/{id}/itinerary returns 409 UNSUPPORTED_ITINERARY_CONTRACT for it. Detail reads retain
the raw archived document. Android gives an explicit unsupported-contract error. Regenerate
such trips; do not relabel their version or pretend they are frontend v2.
